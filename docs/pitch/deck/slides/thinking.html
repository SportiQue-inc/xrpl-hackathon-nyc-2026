How the agent decides

Every request passes four checks, in order. Each answer comes with a reason.

1 · HARD GATES

Prohibited use, no IRB for T2+, expired credential, excluded country, a type she marked “never”

→ blocked. No setting widens it.

2 · TIER

T3 (genome, CT, MRI)?

→ always a fresh yes from her, never automatic.

3 · BUYER GRADE

Buyer trust A–D (credentials, deletion record, audits, disputes) vs her baseline per data type

→ grade ≥ baseline: act.

4 · SCOPE

Inside what she already agreed? New purpose, field, institution type or country?

→ inside: act. New: one package back to her.

Same MRI request

Grade A lab → asks her for a fresh yes. Grade C lab → held without asking: “MRI needs grade A+ and a controlled workspace, buyer is C.”

The LLM proposes, code verifies, the ledger enforces. The LLM can only narrow a request, never widen it (tested).

Here's how the agent thinks. Four checks in order. First, hard gates no setting can widen. Second, the tier: anything T3 goes back to her, every time. Third, the buyer's trust grade against the baseline she set for that data type. Fourth, scope: if it's inside what she already agreed, the agent acts; if it's a new purpose, field, institution type or country, it bundles everything into one package per institution and asks her once. Same MRI request: a grade A lab gets a fresh-approval card; a grade C lab is held without even asking. And the rule underneath: the LLM proposes, code verifies, the ledger enforces. The LLM can only narrow.
