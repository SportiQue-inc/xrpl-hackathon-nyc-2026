AgentRail 정본 워크플로와 화면별 갭

연구자가 기관과 서브 프로젝트를 정하는 순간부터 참여자가 철회하는 순간까지, 모든 화면이 따라야 할 한 가지 흐름입니다. 그 아래에 vault, /try, UniQLab 콘솔, 참여자 웹, UniQdata 앱, Figma가 이 흐름과 어디서 다른지 적었습니다.

확인 방법: railway 사이트는 이 작업 환경의 네트워크에서 막혀 있어서, 배포된 커밋의 소스를 직접 읽었습니다. vault는 claude/project-thread-06we25 a9570ed, /try·콘솔·참여자 웹은 main dbbf23b (PR #61), UniQdata 앱은 fix/home-dailyq-routine-figma e02cf27a입니다. Figma는 직접 열지 않았고, 앱 스레드가 Figma와 비교한 내용을 옮겼습니다.

먼저 정해야 할 것 4가지

1. 지급 비율결정: 엔진 곡선으로 통일 (80/20 문구는 모두 수정)

엔진과 README는 연속성 곡선(첫 주 50%, 연속 주마다 +10%p, 최대 90%)인데, 콘솔·/demo·법률 매핑은 "80% 지급, 20% 검토"라고 씁니다.

2. 금액 단위추천: 어디서나 RLUSD + 각주 한 줄

앱·/demo는 RLUSD, 콘솔·참여자 웹은 test USD, vault는 test USD와 XRP, Figma는 RLU입니다. 테스트넷에서는 "test USD가 RLUSD 대신"이라고 각주로만 밝히면 됩니다.

3. 연구자 콘솔 하나로추천: /console(UniQLab)로 통일

/try의 "study console" 버튼은 /apps/live로 가고, Figma 기반 UniQLab 콘솔은 /console에 따로 있습니다. 서브 프로젝트는 /apps/live에만 있습니다.

4. vault의 자리추천: 트랙 01(일반 데이터 거래) 전용으로 표시

vault는 진단 기록을 받지 않는 일반 데이터 마켓이라 건강 연구 흐름의 시작점이 될 수 없습니다. /try는 vault를 "personal data vault", 곧 UniQdata 역할처럼 소개합니다.

정본 흐름 한 장

초록 참여자가 직접 하는 단계 파랑 연구자·에이전트 단계 · 맨 아래 줄은 그 단계에서 원장에 남는 tx

0단계(한 번만): 기관은 VERIFIED_ORG Credential과 DepositPreauth, IRB는 만료일 있는 윤리 Credential, 연구 금고는 SignerList(PI + 컴플라이언스, 2명 중 2명)와 master key off. 참여자는 UniQdata intake로 기록을 모으고(출처 서명 stamp, MRI·CT·유전체는 DataQ 경로), 에이전트 규칙(자동으로 처리할 범위)을 정합니다.
